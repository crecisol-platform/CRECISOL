## Alcance nuevo de C05-02

**T01, no enumeración de cuentas:** El caso de uso `RequestNeutralRegistrationIntent` no consulta cuentas, ni directorio de email o membresías. Solicitudes sintácticamente válidas conocidas/desconocidas recorren el mismo flujo y reciben `202 / REQUEST_ACCEPTED_IF_ELIGIBLE`, sin correo, estado de usuario, cookie, sesión ni vínculo en respuesta. Direcciones mal formadas reciben también neutralidad pero no se guardan. Se revalida host DNS verificado C04 y tenant ACTIVE mediante puertos backend, nunca se acepta tenant de body, slug, query o X-Tenant-Id. El peer se obtiene del socket del servidor, no de X-Forwarded-For.

**Persistencia cifrada y cuotas:** `MySqlDisposableNeutralRegistrationRecorder` solo permite servidor `127.0.0.1`/`localhost`/`::1` y base `c05_02_disposable`; nunca usa DSN del cliente ni se registra en API. Genera huellas HMAC-SHA256 con claves derivadas separadas para mailbox/peer, scoped por tenant, y cifra el correo normalizado con AES-256-GCM, nonce CSPRNG, AAD tenant+versión+hash; los buffers se limpian. No almacena el email ni la IP en claro. Una rutina MySQL 8.4 `c05_02_record_registration_intent SQL SECURITY DEFINER` aplica cuota atómica de **8 registros por cliente y tenant por ventana de 15 minutos** en InnoDB y responde siempre `ACK` sin revelar cuotas, estados ni existencia de cuentas. El usuario de ingesta solo tiene `EXECUTE`, sin lectura/escritura directas a tablas sensibles. El límite es un valor de ENSAYO y NO una política comercial fija: debe parametrizarse desde backend/administrativo en C05-10.

**HTTP real aislado:** El proyecto de prueba .NET10 inicia Kestrel en `127.0.0.1:0` con rutas `__test_only`; no edita `backend/src/Crecisol.Api/Program.cs` ni activa endpoints de producción. El test usa HttpClient, catálogo de hosts sintéticos A/B, lectura de peer desde transporte, solicitudes con headers de ataque, cifrado/descifrado de control, suspensiones MySQL, ACL, cuota real, host desconocido y ausencia de respuesta de existencia. No se entrega ningún correo: conocido/desconocido son datos sintéticos, no cuentas reales.
