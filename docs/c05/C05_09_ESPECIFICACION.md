## 2. Alcance positivo controlado

- **Perfiles vinculados exclusivamente a tenant+actor+membership verificados:** nunca crear un perfil global compartido entre empresas. El tipo Owner/Employee/Consumer de C05-01 describe UI, no otorga rol, acceso privado, lectura de otro actor o cambio sobre datos ajenos. No SuperAdmin por omisión.
- **Prueba de identidad:** reautenticación C05-04 Argon2id fresca dentro del caso de uso para las pruebas de actualización y consulta. El host debe provenir de backend verificado, no de X-Tenant-Id, URL, claim o email; MySQL revalida versión y estado activos de cuenta, credencial, tenant, host y pertenencia. Los permisos reales basados en sesión + RBAC/ABAC no existen aún; ningún endpoint de producto queda habilitado.
- **PII privada por tenant:** nombre de visualización validado en dominio; almacenar **solo sobre cifrado AES-256-GCM** con nonce aleatorio y datos autenticados AAD por tenant+actor, clave suministrada en test por runtime (no archivo ni código). El registro de auditoría almacena IDs/operación/tiempo solamente; ningún nombre, correo, teléfono, fecha de nacimiento, URL pública o clave se registra. Concurrencia controlada con revisión/CAS de un ganador. Borrado lógico de datos PII y foto, revisión monotónica y bitácora append-only sin PII.
- **Foto de perfil segura:** en DB únicamente `media_id` opaco y metadatos mínimos de **referencia** a objeto futuro Cloudflare. No BLOB, bytes, base64, URL firmada, URL remota proporcionada por usuario ni URI pública permanente. Referencia de prueba con clave canónica de objeto `profiles/<tenant-hex>/<actor-hex>/<media-id-hex>.webp`, MIME detectado por un **catálogo confiable simulado**, archivo privado, tamaño permitido, SHA256 y estado VERIFIED; no se aceptan cargas PENDING/REVOKED, objetos cruzados, rutas inventadas, SVG/HTML, firmas falsas, fotos externas ni rutas `../`. La validación real de bytes, antivirus y bucket Cloudflare se reserva C21/C32; aquí se prueba el contrato de metadatos y la negativa.
- **Lectura privada:** probar HTTP únicamente `127.0.0.1` y MySQL8.4 desechable. El lector autorizado de prueba recibe solo nombre descifrado de su perfil y `media_id`; nunca clave R2, URL de descarga, secret, token o datos de otro tenant. No existe preview ni descarga; futuros capítulos añadirán resolver autorizado con URL de corta vida. Respuestas `Cache-Control: no-store`.
- **Arquitectura:** Domain valida, Application gobierna permisos/reautenticación, CredentialSecurity cifra, Infrastructure usa adaptador MySQL con solo EXECUTE, `database/tests/fixtures/` contiene tablas/procedimientos efímeros, `backend/tests/` compila y ejecuta HTTP real. `backend/src/Crecisol.Api/Program.cs` conserva solo branding público, sin perfiles productivos.

## 3. Negativos y certificación

**P0 — obligatorio:** no lectura cruzada de foto/PII en los dos sentidos A/B ni actor ajeno, aun con URL o id de foto conocidos. Probar host falso, headers manipulados, perfil/medio de actor ajeno, MIME activo/SVG, tamaños fuera de política, media NO VERIFICADA, borrado/revocación, nombre no canónico/controles, replay de revisión/ETag, 16 updates concurrentes con exactamente un ganador, perfil vencido/suspendido, credential revocada, lectura tras borrado, rollback e inmutabilidad de auditoría, SQL sin privilegio SELECT/UPDATE sobre tablas.

**Auditoría A:** Documento Maestro, ADR-015 y dependencia C05-08. **B:** aislamiento de PII y medios, sesión/host/realm, CAS, SQL, cifrado, denegación por defecto. **C:** .NET10, MySQL8.4 real, API pública sin cambios, resultados y regresiones C05-01..08, SHA/diff acotados, rendimiento y UX de lectura privada. Certificación solo cuando A/B/C y pruebas reales sobre SHA final resulten verdes, CI técnica PRE y POSTMERGE, acta documental y CI institucional PRE y POSTMERGE verificadas. Si falla una puerta, corregir y reejecutar sin declarar PASS histórico ni saltar microfase.

**NO-GO productivo:** no hay usuario real autenticado, sesión/claims/roles reales, edición de perfil en UI, subida de bytes, antivirus, detector MIME real, Cloudflare R2/Images, signing/CDN, KMS/rotación, borrado físico/retención legal, preferencias de menores ni auditoría WORM. Solo código y pruebas aisladas. La implementación no habilita C05-10, C05 completo, C06, producción ni pagos.

**Rollback:** cerrar PR antes de fusionar o revertir solo squash técnico/documental C05-09 en dev tras verificar dependencias. Nunca modificar certificados C05-01..08, main, Word/PDF ni el repositorio prohibido `solqaryn/Solqaryn`.
