## Puertas inviolables

1. **Al iniciar capítulo:** comprobar que el capítulo inmediatamente anterior tiene pruebas integrales, auditorías A/B/C, acta y aceptación expresa; verificar SHA del Word, matriz y decisiones pendientes. Solo entonces pasar el plan de ese capítulo de **PROPUESTO** a **PLAN ACTIVO** por PR revisado.
2. **Al iniciar microfase:** la inmediatamente anterior debe tener acta, PR y post-merge en verde. Definir entrega pequeña, pruebas positiva y negativa, impacto frontend/backend/database, riesgos, permisos y rollback. Abrir su archivo individual y rama.
3. **Al cerrar microfase:** build real, tests reproducibles, A trazabilidad, B seguridad/tenancy, C arquitectura/UX/rendimiento; cero P0/P1 sin resolver; último SHA y GitHub Actions verificados; diff sin secretos, PR integrado a dev, post-merge y acta acreditada. No confundir validación estática con prueba real.
4. **Al cerrar capítulo:** `todas las microfases cerradas` es condición necesaria, **no suficiente**. Repetir integración y auditorías de todo el capítulo, revisar requisitos del Word y riesgos, preparar acta y obtener aceptación expresa antes de avanzar.
5. **Al activar proveedores externos:** no desplegar VPS, DNS, Cloudflare, R2, cobradores o producción dentro del alcance actual. Si alguna certificación exige interacción real con proveedor y aún no está autorizada, **BLOQUEADO**: los simuladores no certifican producción.
6. **Prohibiciones:** no modificar `solqaryn/Solqaryn`, no crear ramas protegidas ni configurar reglas de GitHub, no abrir código C02–C37 con C01 no certificado, no publicar secretos, no habilitar endpoint privado sin autorización backend.
